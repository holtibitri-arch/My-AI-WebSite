About

I have been writing software since 2008: .NET and Oracle developer at Monte dei Paschi di Siena, then systems integration, architecture, and leading an innovation unit. Today I am CTO at TIG Factory.

My job has changed shape. Most of the code is now written by AI agents. I decide the architecture, write the rules they work by, set the checks, and answer for what goes to production.

This is not an experiment. It is how I build a trading platform, a podcast that ships every morning without me, and the tools my colleagues at TIG use every day.

Before that I worked inside PwC, Medtronic Italia, Reply (for Eurizon) and Magneti Marelli, spent four years at Nexive and eight at Cloudia Research, from architect to Innovation Director. That is where I learned what software needs to hold up in a company, and it is what I now ask of the agents.

Microsoft certified since 2011 (MCSD, MCTS), Anthropic certified since 2026 (Claude Code, Claude Cowork).

How I work

Five rules,
learned from things that run.

  1. 01

    First, decide whether AI is needed

    A client asked me for AI. Thirty minutes in, it was clear he needed an if statement. Being able to say so is part of the job.

    Read the post →
  2. 02

    Agents get a contract, not a prompt

    Role, rules, sources, what it must never do. Written down, versioned, corrected after every mistake. At TIG Factory the company knowledge base is kept by an agent with one rule at the top: never make anything up.

    Read the guide →
  3. 03

    Sensitive data never reaches the model

    At TIG, a check on the production database used to take half an hour by hand. Now it takes seconds: personal data is masked on the PC and the model only gets the summary.

    Another case: meetings transcribed locally →
  4. 04

    Every step has a check

    An agent that writes without verification produces fast code and slow problems. Tests, review and acceptance live inside the workflow, not after it.

  5. 05

    Decisions stay with people

    Agents propose, write and verify. What to build, on which architecture and when it ships is decided by whoever answers for it.
